Your posting, line by line

  • Automated diagnostic, validation, and remediation frameworks for production GPU hardware (NVIDIA and AMD). I built a validator that reads NVML telemetry directly, plus a CUDA burn test that stresses the card under load. It treats ECC as a datacenter-only feature, so it degrades cleanly on consumer silicon and reports real counters on A100/H100-class cards. The NVIDIA tooling is NVML/CUDA; the same methodology (telemetry, burn-in, thermal/PCIe gating) carries over to AMD via ROCm-SMI, which I'd be glad to learn on the team's stack.
  • Python agents, services, APIs, and Ansible automation. Six small Python programs, one bash verify script, and an Ansible playbook that orchestrates the whole flow: validate, burn, network check, combine, submit.
  • Analyze workload performance, utilization, thermals, and diagnostic output. My burn test samples temperature, clock, power, PCIe link state, and utilization every half second while the card is under load, then reasons about whether the card actually held up.
  • Testing and verification for production onboarding and Return Material Authorization. A serverless gate ingests each report and returns PROVISION, HOLD, or RMA, with an audit trail in DynamoDB. On failure, it captures an evidence bundle: nvidia-smi dump, kernel log, structured report.
  • Tooling that gates hardware deployment. That gate is the whole point. A node never declares itself healthy. It reports raw checks, and the control plane decides.
  • Understanding of DHCP, IPv6, and ICMP. A node that cannot reach the network is dead weight. My network validator checks all three before onboarding is allowed.
  • Document work performed, including commands executed, observations, and outcomes. Every repo has a written walkthrough and a verify script that proves the pipeline works end to end. The audit trail is append-only, not a memory.
